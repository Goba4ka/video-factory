# Постоянный режим линии `celebrity_news`

## Состояние

`ARMED_WAITING_FOR_START`

Линия настроена, но не выполняет поиск, не создаёт run, не загружает медиа, не рендерит и не публикует ничего до отдельной команды пользователя:

> начинаем

Упоминание команды в документации или цитате не считается запуском. Запуском считается новое прямое сообщение пользователя с этой командой. После завершения одного запуска линия снова переходит в `ARMED_WAITING_FOR_START`.

## Обязательный контракт

При каждом запуске до любых исследовательских и производственных действий полностью прочитать актуальные версии:

1. `TOPIC_PACK.json`;
2. `EDITORIAL_PLAYBOOK.md`;
3. `SOURCE_POLICY.md`;
4. `SAFETY.md`;
5. этот `OPERATING_MODE.md`;
6. общие policies и contracts фабрики, на которые опирается выбранный workflow.

Если документы расходятся, применяется более строгий safety/rights gate. Ни популярность темы, ни срочность, ни доступность ролика в интернете не ослабляют контракт.

## State machine запуска

```text
ARMED_WAITING_FOR_START
  -- «начинаем» --> RESEARCHING_SLATE
RESEARCHING_SLATE
  -- 3–5 проверенных тем --> WAITING_FOR_TOPIC_YES_NO
WAITING_FOR_TOPIC_YES_NO
  -- 2–3 одобрены --> REGISTRY_PRODUCTION
  -- меньше 2 одобрены --> RESEARCHING_REPLACEMENTS
  -- все отклонены --> ARMED_WAITING_FOR_START
REGISTRY_PRODUCTION
  -- rights / preview / final decision нужен --> WAITING_FOR_HUMAN_GATE
  -- MP4 + evidence QC + human final review готовы --> REVIEW_MP4_READY
  -- hard gate не пройден --> BLOCKED_WITH_REPORT
WAITING_FOR_HUMAN_GATE
  -- атрибутированное решение --> REGISTRY_PRODUCTION
REVIEW_MP4_READY | BLOCKED_WITH_REPORT
  --> ARMED_WAITING_FOR_START
```

Ответ `да` означает человеческое одобрение только конкретной темы из slate. Ответ `нет` исключает её из текущего запуска. Если одобрено больше трёх тем, в производство идут три темы с лучшим сочетанием актуальности, источников, прав и низкого риска; остальные сохраняются как approved backlog. Если одобрено меньше двух, линия показывает замену и ждёт ещё один короткий ответ `да/нет`, не производя неутверждённую тему.

## Фаза 1: slate по команде «начинаем»

Найти и заново открыть актуальные либо evergreen-источники. Для изменчивых фактов обязателен интернет-поиск на дату запуска. Search snippet, агрегатор и AI-резюме не считаются доказательством.

Показать пользователю компактный slate из 3–5 тем. Для каждой темы указать:

- рабочий заголовок и однострочный хук;
- что именно подтверждено и кем;
- точную причину `why_now` либо честную evergreen-ценность;
- 1–3 прямые ссылки: первоисточник и, когда нужно, независимое подтверждение крупной редакции;
- дату события, дату источника и дату повторной проверки;
- предполагаемый визуальный путь и предварительный rights-риск;
- общий риск `green|yellow|red` с краткой причиной;
- рекомендацию `да|нет` редактора, не выдавая её за решение пользователя.

`Red` не предлагается к производству. `Yellow` может попасть в slate только с ясно названным человеческим gate. Не скачивать производственные ассеты и не начинать композицию до ответов пользователя.

## Фаза 2: управляемое производство 2–3 одобренных роликов

После получения 2–3 `да` не запрашивать микрорешения, которые можно
безопасно принять по тематическому пакету. Однако это `да` не заменяет
атрибутированные человеческие решения `rights`, `preview_review` и
`final_review`; на них queue останавливается.

Канонический порядок берётся только из `factory/lanes/registry.json`:

`research -> privacy_review -> media_discovery -> rights (human) -> media -> script -> voice -> editor -> bgm -> audio_mix -> compiler -> preview_review (human) -> render -> qc_auto_evidence -> caption_transcript -> captions_analyzer -> facts_analyzer -> policy_analyzer -> dedup_analyzer -> visual_analyzer -> qc_evidence_gate -> qc -> final_review (human) -> publisher`

Роли нельзя менять местами или выкидывать из-за наличия готового MP4.
Discovery не даёт прав; media freeze требует human-approved RightsManifest с точным
SHA-256 и всеми `asset_id`. Музыка замораживается отдельно; `audio_mix` создаёт
единственную program mix, а compiler передаёт её в HyperFrames с беззвучным B-roll.
Рендер начинается только после checksum-bound preview approval; после него весь evidence
QC DAG обязан связывать один и тот же render SHA-256.

Автономность не разрешает обход hard gate. Если тема больше не подтверждается, источник изменился, права не очищены или риск нельзя снять безопасной заменой, конкретный ролик получает `blocked` с причиной; вместо него нельзя самовольно производить не одобренную пользователем тему.

## Обязательные HyperFrames/media skills

Каждое производство начинается с актуального skill `hyperframes` как обязательной точки входа. Он читает проектное состояние, выбирает workflow и до написания composition HTML требует актуальный `hyperframes-core`. Для роликов этой линии маршрут выбирается по фактическому материалу: например, `faceless-explainer` для объяснения новости на созданных визуалах либо `general-video` для кастомного монтажа. Маршрут нельзя выбирать только по привычке.

Перед входом в выбранный workflow выполнить предусмотренное skill-инструкциями обновление/установку skills. Для CLI-проверок, snapshots и render использовать `hyperframes-cli`; для motion/creative/keyframes загружать соответствующие доменные skills по реальной необходимости.

Skill `media-use` обязателен для каждого фото, видео, иконки, логотипа, голоса, музыки, SFX, captions, операции с медиа и визуального treatment. Результат `resolve` не является автоматическим разрешением на коммерческое использование: lane принимает файл только после item-level проверки по `SOURCE_POLICY.md` и записи в rights ledger. Синтетический образ или голос реальной знаменитости запрещён.

## Медиа и rights freeze

До монтажа каждый реально используемый ассет получает запись:

- стабильный `asset_id` и локальный путь;
- каноническую landing page;
- автора и правообладателя;
- license/permission basis и локальную копию доказательства;
- допустимость коммерческого использования, изменения, синхронизации и всех целевых платформ;
- территорию, срок и обязательную атрибуцию;
- проверки likeness, performance, music, trademark, privacy и property rights;
- время получения и SHA-256 замороженного файла;
- точные появления на timeline.

Нельзя помещать в композицию временный файл «на замену», если у него нет прав. Когда права на звёздное фото или видео отсутствуют, использовать допустимые замены из `SOURCE_POLICY.md`: собственную типографику, таймлайн, диаграмму, лицензированный предметный сток, public-domain фон или абстрактную неузнаваемую иллюстрацию.

## Fail-closed safety

### Медицинский gate

Не диагностировать и не выводить состояние по внешности, паузе, поведению или словам третьих лиц. Тема блокируется при необходимости использовать непроверенный диагноз, лечение, зависимость, причину смерти или детали кризиса. Даже прямое заявление требует минимизации вреда и отдельного редакционного решения по общественной необходимости.

### Приватностный gate

Блокировать скрытые адреса, контакты, документы, переписку, маршруты, текущую геолокацию, непубличных детей и родственников, папарацци, утечки и частную съёмку. Публичность человека не является согласием на распространение этих данных.

### Военно-исторический gate

Если тема, архив или визуал затрагивает войны, вооружённые формирования, военную форму, награды, коллаборационизм, репрессии, насилие или спорную историческую идентификацию, нужны профильный первичный/архивный источник, независимая историческая проверка, точные дата и место, корректная атрибуция формы/символики и отдельный человеческий editorial-safety review. Не романтизировать насилие, не использовать графические кадры и не переносить исторический материал на текущие события. При неоднозначной идентификации или риске раскрыть современные оперативные сведения — `blocked`.

### Общий stop

Слухи, диагнозы, непроверенные отношения, беременности, смерти, клеветнические формулировки, скрытая личная информация, старое событие под видом нового, deepfake и неочищенные права всегда блокируют выпуск.

## Структура run

Все файлы одного запуска сохраняются только внутри:

`factory/runs/YYYY-MM-DD/celebrity_news/`

Рекомендуемая структура:

```text
factory/runs/YYYY-MM-DD/celebrity_news/
  RUN_STATUS.md
  slate.json
  approvals.json
  <topic-slug>/
    source_registry.json
    claim_ledger.json
    media_discovery_manifest.json
    rights_manifest.json
    rights_human_approval.json
    frozen_media_manifest.json
    SCRIPT.md
    shotlist.json
    captions.srt
    voice_manifest.json
    voice_rights_approval.json
    bgm_manifest.json
    program_audio_manifest.json
    hyperframes/
    render_project_manifest.json
    preview_approval.json
    render_manifest.json
    qc_auto_evidence_manifest.json
    caption_transcript_manifest.json
    qc_analyzer_reports/
    qc_evidence_bundle.json
    qc_report.json
    final_review.json
    checksums.sha256
    review.mp4
```

Имена могут дополняться требованиями актуальных общих contracts, но не перемещаются за пределы run-каталога. Кэш инструмента, если он технически создаётся вне run, не считается deliverable и не должен содержать единственную копию доказательства.

## Минимальный QC контрольного MP4

- длительность каждого ролика 60–80 секунд;
- вертикальный кадр 9:16, целевой master 1080×1920;
- captions синхронны, читаемы и совпадают с финальным текстом;
- ни один существенный факт не выходит за claim ledger;
- даты и архивная маркировка видимы там, где нужны;
- каждый timeline-ассет присутствует в rights ledger и render manifest;
- отсутствуют placeholder, watermark, нелицензированная музыка, синтетическое лицо/голос знаменитости и неразрешённые приватные данные;
- проверены звук, пики, чёрные/битые кадры, safe margins, орфография и финальный кадр;
- combined auto evidence, word transcript, captions/facts/policy/dedup/visual
  analyzer reports и immutable evidence bundle прошли на том же render SHA-256;
- SHA-256 контрольного MP4 и всех финальных артефактов сохранён.

Контрольный MP4 является локальным review-артефактом, а не разрешением на публикацию.

## Запрет внешней публикации

Линия не загружает, не планирует и не публикует ролики в YouTube, TikTok, Instagram или другие внешние сервисы без нового отдельного явного разрешения пользователя после просмотра контрольных MP4. Одобрение темы словом `да` разрешает исследование и локальное производство, но не публикацию. Команды HyperFrames `publish` и любые внешние posting-интеграции остаются запрещены до такого разрешения.
