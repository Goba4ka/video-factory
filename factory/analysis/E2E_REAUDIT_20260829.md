# E2E re-audit after the server-migration slice

Date: 2026-08-29. Scope: five production lanes, 10-15 files/day target.

## Closed in this slice

- Editorial handlers now return the queue-required `result.artifact` wrapper.
- `editor` is a schema-bound Codex role; shotlist timelines receive semantic
  continuity/source-range validation.
- Scout emits only `war_history`, `celebrity_news`, `motivation`,
  `chinese_medicine`, and `health`; hook/audience are Russian and uncertain
  discovery stays behind a closed research gate.
- Wheel and sdist carry all 16 canonical schemas; isolated installs load them,
  and server preflight fails closed when schema package data is incomplete.
- A deterministic `voice` handler connects a passed Russian ScriptPackage to
  Fish Audio, requires job-bound voice rights, keeps the two-generation ledger,
  avoids a duplicated hook, and is exposed by a dedicated credential-isolated
  systemd unit. Motivation cannot use this worker.
- The migration guide now separates implemented server components from the
  desired final topology and includes a no-go cutover checklist.
- Full Python suite: `202 passed, 2 skipped, 15 subtests passed`; the two gated
  wheel/sdist install smokes pass separately (`2 passed`).

## Still blocking unattended MP4 production

1. Live discovery does not yet guarantee 10-15 fresh, relevant candidates. An
   offline five-lane smoke returned eight honest evergreen candidates; it did
   not pad the slate to the requested quota.
2. Research/rights tasks still need one immutable ProductionContext containing
   approval, date, Topic Pack, intended use, destinations, candidate assets and
   license library.
3. Media selection/freeze is a manual CLI, not a queue stage, and no queue
   contract binds its verified file hashes to editor/render.
4. Motivation has no `source_audio` handler for licensed original speech.
5. No compiler turns ScriptPackage + Shotlist + frozen assets into a complete
   HyperFrames project.
6. Render wrapper accepts an existing project but is not a queue handler that
   creates and returns a canonical RenderManifest.
7. Technical FFmpeg QC exists, but semantic caption/fact/rights/safe-zone/style
   QC is not a deterministic queue gate.
8. Successful queue artifacts do not yet move the job state to `ready` or create
   a pending outbox record.
9. There is no daily systemd orchestrator for discovery, approval intake,
   launch and outbox preparation.

## Current decision

Server migration is safe for shadow queue work, seven editorial roles and
controlled Fish voice jobs. It is **not** safe to advertise as unattended
10-15 MP4/day production. The next acceptance unit is one already-cleared
health bundle:

```text
approved IdeaCard
-> research/safety/rights/script
-> frozen media hashes
-> Fish VoiceManifest
-> Shotlist
-> generated HyperFrames project
-> real 1080x1920 MP4
-> technical + semantic QC
-> job ready
-> outbox pending_approval
```

Only after that command succeeds without hand-created intermediate files should
the same slice be implemented for motivation, followed by a mixed batch of five
and real 15/30 shadow batches.
